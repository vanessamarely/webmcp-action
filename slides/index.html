Model Context Protocol

Un estándar abierto para que los modelos descubran e invoquen capacidades externas — sin construir una integración a medida por cada aplicación.

01 · ORIGEN
Creado por Anthropic, noviembre 2024. Especificación abierta en modelcontextprotocol.io.
02 · ADOPCIÓN
Hoy lo integran OpenAI, Google, Microsoft, editores como VS Code y Zed, y una comunidad enorme de servidores.
03 · ANALOGÍA
Se describe como el «USB-C de las apps de IA»: un puerto estándar en vez de un cable distinto por integración.

MCP Server

Un proceso independiente de cualquier app de IA. Es el backend real: inventario, base de datos, APIs internas.

01 · DECLARA
Nombre, descripción y JSON Schema por cada tool.
02 · AGNÓSTICO
No sabe (ni le importa) qué LLM lo está usando.
03 · REAL
Descuenta stock de verdad — no es una simulación.
mcp-server/src/tools.ts
server.registerTool(
  "place_order",
  {
    description:
      "Descuenta stock real.",
    inputSchema: {
      product_id: z.string(),
      quantity: z
        .number().positive(),
    },
  },
  async ({ product_id, quantity }) => {
    const r = placeOrder(
      product_id, quantity
    );
    return ok(
      `Pedido ${r.id} confirmado.`
    );
  }
);

MCP Client

Conecta al server, le pasa sus tools al LLM y ejecuta lo que el modelo decida llamar.

01 · DISCOVER
client.listTools() — pide la lista de tools del server.
02 · DECIDE
El LLM (Claude o Gemini) decide si necesita llamar alguna.
03 · EXECUTE
client.callTool() ejecuta y devuelve el resultado al LLM.
! Mismo protocolo con Claude o Gemini — un adaptador intercambiable, cero cambios en el server.
mcp-client/src/llm/claude.ts
for (let i = 0; i < MAX_STEPS; i++) {
  const res = await client
    .messages.create({
      model, tools, history,
    });

  const calls = res.content
    .filter(b =>
      b.type === "tool_use");

  if (!calls.length)
    return res.text;

  for (const c of calls) {
    const t = await runTool(
      c.name, c.input
    );
    history.push(t);
  }
}

¿Y si las tools viven en la página?

WebMCP es un estándar web propuesto para que cualquier sitio exponga su funcionalidad como tools — invocables por un agente que corre dentro del propio navegador.

01 · DÓNDE
Las tools se registran en la propia página con document.modelContext.
02 · QUIÉN
Impulsado por el equipo de Chrome, dentro del Web Machine Learning Community Group.
03 · ESTADO
Borrador activo — github.com/webmachinelearning/webmcp, evolucionando en público.

document.modelContext

01 · REGISTER
registerTool(tool, { signal }) — nombre, descripción y JSON Schema. El signal permite desregistrarla al navegar.
02 · DISCOVER
getTools() — lista las tools registradas en la página en ese momento.
03 · EXECUTE
executeTool(tool, args) — la invoca y espera su resultado.
! Origin isolation + permissions policy: una tool solo es visible para agentes del mismo origen, salvo allow="tools" explícito.
! Las tools cambian con la navegación — evento toolchange para reaccionar en vivo.
web/src/product-tools.ts
await document.modelContext
  .registerTool(
    {
      name: "change_color",
      description:
        "Cambia el color",
      inputSchema: {
        hex: { type: "string" }
      },
      execute({ hex }) {
        scene.setColor(hex);
        return ok("listo");
      },
    },
    { signal }
  );

Lo último: tools de debugging

webmachinelearning/webmcp #253 — agrega un miembro debugging a ToolAnnotations para separar tools pensadas para desarrolladores de las tools para el usuario final.

01 · PROBLEMA
DevTools, frameworks de testing y utilidades de debug se mezclaban con las tools reales de la app.
02 · SOLUCIÓN
Un booleano debugging: true — un agente de propósito general puede filtrarlas.
03 · POR QUÉ ESE NOMBRE
debugging, no debuggingHint: es una categorización definitiva del propósito, no un hint de comportamiento.
! Discusión abierta: debugging: true probablemente no debería combinarse con consequentialHint — parecen mutuamente excluyentes.
webmcp · ToolAnnotations
document.modelContext.registerTool({
  name: "run_test_suite",
  description: "Corre los tests de la app.",
  annotations: {
    debugging: true, // ← nuevo en #253
  },
  inputSchema: { type: "object" },
  async execute() { /* … */ },
});

MCP

  • Proceso backend separado.

No compiten. Se complementan.

En el navegador — WebMCP. Configurar un producto, navegar el catálogo, llenar el carrito — tools que actúan sobre lo que el usuario ya está viendo.

En el backend — MCP. Confirmar el pedido de verdad, verificar stock real, cobrar — tools que protegen datos y reglas de negocio detrás de un servidor.
